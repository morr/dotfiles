# Локальные патчи скиллов

Здесь лежат инструкции по повторному наложению правок на скиллы из `~/.claude/skills/`,
которые **устанавливаются из внешнего источника** и потому затираются при обновлении.

Один файл = один пропатченный скилл, имя файла = имя скилла.

Формат каждого файла: что делает апстрим, что и почему меняем, точные правки, как проверить.
Файлы живут **вне** директории скилла — иначе переустановка снесла бы и сам патч.

Секция «Правки» описывает **текущее состояние** скилла, а не историю: изменилось поведение
патча — правится сама секция, а хронология уходит в «Историю правок» в конце файла.
Дописывать «Дополнение от такого-то числа» поверх устаревшего текста нельзя — тот, кто
накладывает патч, начнёт восстанавливать отменённые куски. Блок «Проверка» правится вместе
с секцией «Правки»: устаревший grep даёт ложное «патч не наложен».

## Как этим пользоваться

После обновления/переустановки скилла из первоисточника:

> Перечитай `~/.claude/local-patches/<имя-скилла>.md` и наложи описанный там патч заново
> на `~/.claude/skills/<имя-скилла>/`.

Если апстрим изменился настолько, что патч не ложится дословно — примени его по смыслу
и обнови сам файл патча под новый апстрим.

## Пересборка патча

Файл патча пишется по ходу правок и потому дрейфует: описанное состояние расходится
с тем, что лежит на диске. Пересборка — это сверка с **фактическим** диффом, а не
вычитка текста:

```sh
git clone --depth 1 https://github.com/mattpocock/skills.git /tmp/upstream-skills
diff -u /tmp/upstream-skills/skills/engineering/<имя>/SKILL.md ~/.claude/skills/<имя>/SKILL.md
```

Дальше по этому диффу: каждый его кусок должен быть описан в «Правках» — и в том порядке,
в каком идёт в файле скилла; описанное, но отсутствующее в диффе — устаревший текст, его
переписывают; дописанные сверху датированные блоки сворачиваются в разделы по шагам,
а даты уходят в «Историю правок». В конце прогоняются все команды из «Проверки»: они
должны отработать на текущем скилле, иначе правится и она. Апстрим сам мог уйти вперёд —
несовпадение с ним отмечается в «Что делает апстрим», а не молча подгоняется.

## Текущие патчи

- [improve-codebase-architecture.md](improve-codebase-architecture.md) — два патча: отчёт публикуется артефактом, а не HTML-файлом в `/tmp` с CDN; вопросы задаются через `AskUserQuestion`, а не текстом `❓ Q1 / ➡️`.
- [code-review.md](code-review.md) — описание PR читается как часть спеки (зафиксированные там расхождения с issue — решения, а не находки); вместо summary всех находок скилл идёт обходом по одной issue — сам цикл вынесен в репозиторный скилл `issue-walk`, а `code-review` заполняет его слоты; плюс три необязательных аргумента (точка отсчёта, модель планировщика, режим `manual|auto`), закрытие ветки коммитом, пушем и `/pr_description`, и экономия контекста — саб-агенты уходят одним блоком в одном сообщении, а спека, тело PR, baseline запахов (`smells.md`) и протоколы волны `auto` доходят до них путями к файлам, а не пастами.
